Why this stands in for the physician-mortgage market. HMDA records an applicant's income and loan amount but not their occupation — no field says "physician." Ranger's proposed physician mortgage targets high-income professionals who buy above the conforming-loan limit (jumbo). We proxy that demand with the average purchase-loan size per county: markets with the largest average purchase originations are where jumbo, high-income borrowers — physicians among them — concentrate. This is an inference from loan size, not an identification of physicians.

Methodology & sources

Data source

HMDA (Home Mortgage Disclosure Act) data, pulled live from the CFPB / FFIEC data browser aggregations API (ffiec.cfpb.gov/v2/data-browser-api); free, no key. Every request carries a browser User-Agent header — the API returns 403 without one. We use the aggregations endpoint (grouped counts and loan-amount sums), never the row-level endpoint, which runs to millions of records.

Query parameters

  • Geography is passed as counties={5-digit state+county FIPS} with no states parameter — when both are sent the API silently ignores the county and returns the whole state. Each of the 33 footprint counties is queried on its own FIPS code.
  • Originations, denials, applications: actions_taken=1,2,3,4,5 returns one row per action — originated (1), approved-not-accepted (2), denied (3), withdrawn (4), closed-incomplete (5).
  • Purpose mix: actions_taken=1&loan_purposes=1,2,31,32,4 — purchase (1), home-improvement (2), refinance (31), cash-out refinance (32), other (4). Refinance below combines 31 + 32.
  • Each aggregation row carries count (loans) and sum (total loan amount, in dollars).

Definitions

  • Originations — applications that closed as loans (action taken = 1), by count and by dollar volume.
  • Denial rate — denied applications ÷ all completed applications = action 3 ÷ (actions 1+2+3+4+5). Purchased loans (action 6) and pre-approvals (7, 8) are excluded, so this is a decision rate on applications the lender actually worked.
  • Purpose mix — share of originations that are purchase vs. refinance (incl. cash-out) vs. home-improvement / other.
  • Average purchase size — dollar sum ÷ count of purchase originations; the high-income / jumbo proxy.

Limitations & caveats

  • No occupation field. HMDA has applicant income and loan amount but does not identify a borrower's profession — physicians are inferred through the high-income / jumbo segment, never directly identified. The proxy is average purchase-loan size, not a hard jumbo threshold; the API cannot filter aggregations by loan amount.
  • ~1-year lag. HMDA is annual; institutions file by March 1 for the prior year, so the latest published year trails the calendar. This dashboard auto-selects the latest year the browser serves.
  • Aggregations, not loan-level. Every figure is a grouped count or dollar sum; individual loans are never pulled.
  • Lender / market share is not shown. The aggregations endpoint groups only by the categorical HMDA fields above — it exposes no lender / LEI grouping dimension — so a ranked lender-share view cannot be built from this endpoint without descending to the row-level data. It is omitted rather than approximated.
  • The map places each county at its geographic centroid (a fixed coordinate table), not at the location of individual properties, which HMDA aggregations do not provide.
